# Cible Cloudflare, désactivée

Le dépôt GitHub reste la source ; GitHub Pages sert le site actuel. Ce Worker et `dist/` n'ont pas été déployés. Les routes API répondent 503 tant que les indicateurs ne sont pas activés. `workers_dev=false` et `preview_urls=false` ferment aussi les URL publiques implicites ; une future préproduction nécessitera une configuration d’accès isolée approuvée. La date de compatibilité Workers est fixée au 6 août 2026, alignée sur la version épinglée du moteur natif utilisé en QA ; tout relèvement demandera une nouvelle recette. Prévisualiser dans un environnement distinct après création d'un compte Cloudflare, d'une base D1 (`CONVERSION_DB`), du Durable Object, d'un secret `GUARD_HMAC_KEY` et des variables Brevo. Compléter le binding D1 et `ALLOWED_ORIGIN` dans une configuration de préproduction séparée ; ne jamais enregistrer les valeurs sensibles dans Git. Construire `dist/` via `quality/scripts/build_dist.py` avant tout contrôle local. L'activation des indicateurs et du beacon exige un GO séparé.

`/api/events` stocke exclusivement des compteurs par jour et dimensions fermées. La garde distribuée limite par clé HMAC issue de l'IP et ne conserve ni IP brute ni contenu de lead. D1 doit confirmer l’incrément avant la réponse 204 ; superviser les erreurs Worker et valider les compteurs lors de la recette. Les appels Brevo restent non transactionnels : un échec après upsert peut demander un rapprochement manuel.

Avant une activation distincte : fixer la durée de conservation des agrégats D1 et sa purge, revoir le texte de confidentialité avec le responsable, vérifier la livraison des trois appels Brevo en cas d'échec partiel, mesurer les limites réelles de débit et de taille sur préproduction, et exécuter un test de charge. Aucune configuration de domaine, D1 ou secret n'est fournie par ce dépôt.

## Préproduction et retour arrière

Après autorisation distincte, créer les bindings D1 et Durable Object isolés et installer les secrets uniquement dans le compte Cloudflare. Déployer en préproduction sans domaine actif, avec `LEADS_ENABLED=false`, `EVENTS_ENABLED=false`, `NEWSLETTER_ENABLED=false`. Vérifier le rendu et les compteurs avec données factices, puis préparer les textes d’information. Conserver GitHub Pages actif. En cas de problème après une future bascule, désactiver les flags, remettre le routage DNS antérieur documenté et contrôler les demandes possiblement reçues ; ne pas supprimer les données et ne pas changer les enregistrements mail MX/SPF/DKIM/DMARC lors d’un rollback web. Le domaine et l’activation exigent un GO distinct.
